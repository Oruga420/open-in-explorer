1Where it standsBuilt and published; the only step left is loading it in Chrome.

The extension and its native helper are complete and pushed to github.com/Oruga420/open-in-explorer (public). Pressing the toolbar button (or Alt+Shift+E) reads the current tab's URL, pulls a Windows path out of it, and hands that path to a small Python native messaging host that runs explorer.exe — with /select when the path is a file, so the file shows up highlighted inside its folder. The host is already installed here: host\install.ps1 wrote the launcher and host manifest and registered it for Chrome, Edge and Brave, and the extension id is pinned by the manifest key (dahclepccpmepheckhenjdkfclfhdjib) so the allow-list matches on any machine. What has not happened yet: the extension is not loaded in Chuck's own Chrome profile — chrome://extensions → Developer mode → Load unpacked → C:\Users\user\Desktop\oruga projects\open-in-explorer\extension, then restart Chrome.

5DecisionsExplorer needs a native host; the extension id is pinned so the allow-list holds.
DateDecisionWhy it beat the alternative
2026-09-10Native messaging host instead of just opening file:/// in a tabA file:// tab is Chrome's own directory listing, not Explorer; the goal was a real Explorer window with the file selected.
2026-09-10Pin the extension id with a manifest keyThe host's allowed_origins has to name the id; without a fixed key every unpacked load gets a new random id and the installer would need re-running.
2026-09-10explorer.exe /select,<file> for file pathsHighlights the file inside its folder without launching it — the host never executes what it is handed.
2026-09-10Python + .bat launcher rather than a compiled hostPython is already on this machine and the host stays readable in a public repo; the console flash is avoided by pointing at pythonw.exe.
2026-09-10Public GitHub repoExplicit operator instruction, overriding the usual private-personal-repo default.
